# HC5761 适配说明（非 HC5761A）

HC5761 使用 MT7620A、128 MiB RAM、16 MiB SPI NOR 和 MT7610E（5 GHz 1T1R）。
新增配置复用 PSG1218 的 MT7620 构建路径，并采用 MI-MINI 已有的 128 MiB / USB 内核配置，
将 5 GHz 驱动改为 MT7610E；2.4 GHz 使用现有 2.7 驱动，配置为内置 PA / 内置 LNA，
5 GHz 的外置 PA 路径由 MT7610E 驱动读取 EEPROM 后选择。
默认采用精简路由配置，保留双频 Wi-Fi、有线网络、IPv6 和中文 Web 管理界面。
默认关闭所有可选工具和服务，包括 SSH/SFTP、FTP、校园网认证、网页终端、媒体服务、
测速/诊断工具、IPSet 和 NAPT66。USB、SD、磁盘文件系统、摄像头及音频模块也不编译。
板级 GPIO 和 USB 端口定义仍描述实际硬件，USB/SD 功能默认不可用。

硬件映射参考 OpenWrt 24.10 的
[HC5761 DTS](https://github.com/openwrt/openwrt/blob/openwrt-24.10/target/linux/ramips/dts/mt7620a_hiwifi_hc5761.dts)、
[HC5x61 公共 DTSI](https://github.com/openwrt/openwrt/blob/openwrt-24.10/target/linux/ramips/dts/mt7620a_hiwifi_hc5x61.dtsi) 和
[网络初始化](https://github.com/openwrt/openwrt/blob/openwrt-24.10/target/linux/ramips/mt7620/base-files/etc/board.d/02_network)：

| 项目 | HC5761 配置 |
| --- | --- |
| 交换机 | WAN = 0，LAN1 = 1，LAN2 = 4；LAN 插口顺序待实机确认 |
| 复位键 | GPIO 12，低电平有效 |
| LED | 系统 9、Internet 11、2.4 GHz 72、5 GHz 7，均低电平有效 |
| USB 供电 | GPIO 13，高电平开启 |
| 无线 EEPROM | Factory + 0x0000 / + 0x8000 |
| LAN MAC | 优先读取 bdinfo 的 `Vfac_mac`，缺失或无效时回退到 Factory + 0x0004 |
| WAN MAC | LAN MAC + 1，包含跨字节进位；用户配置的 WAN MAC 克隆仍可用 |

有线 MAC 读取策略与 OpenWrt HC5761 的初始化一致。读取 bdinfo 时检查字段格式及
单播地址有效性；初始化不向 Factory 写入有线 MAC，也不修改只读 bdinfo。
直接写入有线 EEPROM MAC 的命令对 HC5761 返回不支持，避免误改无线校准区中的 MAC；
需要调整 WAN 地址时使用 Web 界面的 MAC 克隆设置。无线 MAC 仍沿用各自 EEPROM 数据。
硬件可使用现有 MTK MMC 驱动及轮询卡检测，但精简配置关闭 MMC。

PA/LNA 配置依据为用户提供的完整 Flash dump 中的 Factory 数据：

| 射频 | Flash 偏移 | 原始值 | 解析结果 |
| --- | --- | --- | --- |
| MT7620 2.4 GHz | `0x40036` | `0x0000`（小端 16 位） | 外置 PA 标志与外置 LNA 标志均未设置 |
| MT7610 5 GHz | `0x48034` | `0x0511`（小端 16 位） | 1T1R，`PAType=1`，5 GHz 外置 PA |
| MT7610 5 GHz | `0x48036` | `0x1008`（小端 16 位） | 5 GHz 外置 LNA 标志已设置 |

因此 HC5761 不直接沿用 PSG1218 的 2.4 GHz 外置 PA/LNA 编译选项。保留设备原有
Factory 校准数据，不用默认 EEPROM 样本覆盖。U-Boot 的独立重编不影响这些 Factory 字段。

构建命令（先按 [WSL 编译指南](build-wsl.md) 安装工具链和依赖；WSL 下的 sudo 构建命令也见该指南）：

```sh
cd trunk
fakeroot ./build_firmware_tmp HC5761
```

分区采用 Padavan 布局，不能作为原厂升级包或 OpenWrt sysupgrade 包直接使用。
Bootloader 保持在 0x000000，Factory 保持在 0x040000，固件从 0x050000 开始。
Padavan Config 使用 0x030000–0x03ffff（原厂 hw_panic 区域会被配置数据替代）；
Storage 使用 0xf40000–0xfbffff（512 KiB）。0xfc0000 之后的 oem、bdinfo、backup
保留为只读分区，固件最大长度为 0xef0000 字节（含 64 字节头），打包时拒绝超限镜像。
首次刷入需使用支持该布局的引导器，并事先备份完整闪存和 Factory 校准数据。

已在 Debian 13 / WSL 上使用项目预编译 GCC 7.4.0 工具链和 GNU Make 4.3 完成整包构建，
并验证通过 `build_firmware_tmp HC5761` 在仓库外的临时副本中构建。
上述基础版本通过镜像头 CRC、数据 CRC、内核解压、SquashFS 边界及驱动模块检查。
Factory 数据核对后的 PA/LNA 和 MAC 修正通过内核配置检查、MAC 解析/回退边界测试，
以及 rc 的 MIPS 交叉编译和链接检查；此修订仍需重新构建固件并实机验证。
具体环境准备和构建命令见 [WSL 编译指南](build-wsl.md)。
上机需检查串口（115200）、128 MiB 内存识别、
两个 LAN 与 WAN 的隔离/连通、双频无线及 MAC、IPv6、全部 LED/复位键，
以及保存配置、重启和固件升级后原厂保留分区是否完整。
